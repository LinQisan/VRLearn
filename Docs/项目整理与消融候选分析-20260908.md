# 项目整理与消融候选分析

日期：2026-09-08。原则：保持已有行为、场景 GUID、实验条件与数据兼容性。本轮只落实可证明不改变业务执行的清理，不引入消融开关，不调整模型参数。

## 范围与证据

- 本项目是 Unity 6000.3.19f1 的 VR 交通安全体验/实验系统。当前构建启用 Meta 标题和 Meta 游戏两个场景；旧 OpenXR 标题、游戏场景仍保留，但构建禁用。没有在自有业务代码中发现机器学习训练、学习型特征工程、损失函数或训练数据划分；下文“模型”指事故动力学与交互规则，不虚构训练模块。
- 检索 Assets、Packages、ProjectSettings 中 1,914 个可读文本文件，形成 72 个业务脚本的源码名称引用与资产 GUID 引用清单；进一步阅读关键启动、交通、事故、录制、结果、重试及测试代码。覆盖未启用场景，不能把“不在当前构建”当作“无用”。
- 补查运行时 AddComponent、Resources.Load、Shader.Find、SceneManager、编辑器菜单与迁移入口、测试反射及序列化字段。测试调用 GetMethod/GetField/Type.GetType，简单文本次数不能认定 public API 或字段未用。
- 静态清单是候选筛选，不是完整的 Unity 依赖证明：不反编译第三方 DLL，不声称覆盖外部 AssetBundle、项目外分析脚本或未导入的历史资产。没有据此批量删除脚本、模型、字体或包。
- 项目使用 `.plastic` 工作区，非 Git；已有历史备份继续保留。本轮建立独立修改前备份和 SHA-256 清单，避免覆盖历史恢复点。

主调用链：MetaGameplaySceneSetup → HybridAccidentPresentation（运行时挂载）；GameDirector → ScenarioRuntime / GameplayFlowController；CarFactory → VehiclePool → CarController → MetaVehicleImpactSensor → 事故流程 → AvatarPresenter / AccidentTrajectoryReplay / AccidentOverheadView → AccidentResultPresenter。CSVPrinter 接收 GameDirector 与 CarController 的采样；返回菜单保存，重试是另一条路径。

轮胎转动可作为低优先级纯视觉消融，先于删除 VehicleWheelVisuals 比较运动判断和渲染开销。对象池属于工程优化，可做性能对照，不能据此认定是非必要实验因素。车体接触感应、道路贴地、移动冻结、结果兜底和回收复位属于运行正确性约束，默认不作为第一批消融。

### 实验比较方式

1. 先修复 D 中的数据完整性与条件可辨识问题，再开展消融。保存项目/配置哈希、Unity/包锁版本、设备与输入模式、实际情景ID、实验组、随机种子/生成计划、单位和采样时间基准。已有 CSV 保持原样，新增有版本的旁车会话清单与事件表更容易兼容旧分析。
2. 首批优先 C1、C4、C8、C9，一次一个因素；之后按假设组合少量交互项。C10–C13 往往本来就是实验自变量，不能因“可关闭”而认定冗余。C6/C7 先完成模拟敏感性和边界检查。
3. 同一情景、行进模式和设备内比较；Editor 键鼠与 Quest 分开统计。随机或平衡呈现顺序；多次重试标注 trial index，避免熟悉效应混入效果。固定环境参数不等于固定交通序列；物理模拟也不承诺跨设备逐帧确定。
4. 预先指定每个假设的主要指标与可接受差异，按参与者/试次汇总差值、效应量与区间估计；不把逐帧样本当独立参与者，不用“没有显著差异”直接证明等效。样本量由目标差异与先导方差决定，本轮没有实际参与者数据，不能给出效果结论。
5. CSV 现有数据主要是车辆位置、体验者位置/欧拉角和少量阶段标记。知识/延迟记忆/不适/退出原因、GPU帧时、接触事件、视线注视等并未完整记录，需另采集；相机朝向仅是视向代理，不是眼动。

### 高优先级：会影响数据与解释
