# 交通事故体验：结构、改动与验收

## 项目结构

项目使用 Unity 6000.3.19f1、Meta XR、OpenXR 和 URP。正式入口为 `Assets/_Project/Scenes/TraficAcidentTitle_Meta.unity`，体验场景为 `Assets/_Project/Scenes/TraficAcident_Meta.unity`。旧版非 Meta 场景仍保留。

- `Assets/_Project/Scripts`：标题参数、玩家控制、交通生成、事故与结果流程。
- `Assets/_Project/ScenarioDefinitions`：0–9 共 10 种情景；6、7、9 为自行车，其余为步行。
- `Assets/_Project/Prefabs`：直行、转弯、侧撞车辆等。
- `Assets/ThirdParty`：车辆、建筑、道路、人物和动作模型。
- `Assets/_Project/Tests`：场景引用、车辆复用和体验流程测试。
- `Builds`：Android 构建产物。旧 APK 不包含本轮新增功能。

## 本轮体验流程

选择情景与环境 → 步行/骑行并观察交通 → 真实车体接触触发事故 → 冲击、人物/自行车倒地 → 事故前轨迹回放 → 事故后俯视观察 → 情景说明与速度复盘 → 同条件重试或返回菜单。

正常到达终点继续沿用原有成功返回路径。事故编号、道路、出生点、天气与手机分心配置沿用已有场景。

## 优化内容

1. **轨迹回放**：车辆和体验者各保留最近 121 个姿态样本，约 6 秒、20 Hz，循环缓存不会随体验时长增长。碰撞时截取双方共有时间段，以独立的可视车辆副本和水色体验者标记回放。黄线表示车辆轨迹，水色线表示体验者轨迹；俯视镜头保持稳定并框住整段路径。其他交通仍显示碰撞后位置，界面明确说明这一点。
2. **真实速度**：在事故状态冻结车流前获取实际路点行驶速度，避免把目标巡航速度误当碰撞速度。零速接触不再凭空产生 2 m/s 的最低冲击。
3. **模型表现**：现有 `BodyMain` 和保险杠网格按接触位置作有限局部凹陷，幅度随速度变化；碰撞体保持稳定。只复制发生碰撞的可读网格，不改共享模型文件，回收车辆时恢复原始网格。车轮按实际位移转动，重用时复位。四个车辆预制件分别关闭 1–7 个原本使用透明材质的碰撞辅助渲染器，清除反光矩形并减少无用绘制，碰撞体保留。
4. **VR 视角**：默认不把布娃娃的翻滚旋转施加到 XR Origin，保留头部追踪和身体位移；可通过 `HybridAccidentPresentation.followBodyRotation` 恢复旧旋转效果。
5. **复盘与重试**：结果显示本次接触车速和有效记录时长，增加“同じ条件で再体験”。键盘 R 使用相同重试逻辑，保留场景、身高、体重、天气、时间、手机等参数。
6. **显示可靠性**：回放和结果页让体验相机只渲染 UI，独立俯视相机负责场景画面，避免倒地模型挡住说明与按钮。新增日文字形已烘焙到既有字体，保持场景引用不变。
7. **结束保障**：提前进入结果页会停止尚未完成的演出协程、恢复被回放隐藏的模型并停止震动，避免结果页后残留回放或重新遮挡画面。

本轮直接优化现有 Unity 模型的运行表现，没有重做 Blender 原始模型或改变道路布局。

## 使用

在 Unity 打开 Meta 标题场景并点击 Play。编辑器中 W/A/S/D 移动，按住鼠标右键观察，鼠标点击界面；结果页可点击重试/返回，Enter 返回，R 重试。Quest 使用已有手柄移动与射线交互，A/X 返回。

## 实现边界

这是交通安全体验中的运动记录与可视化，并非用于事故鉴定的重建系统。局部车损是有限美术变形；人体冲量和车辆碰撞后滑行沿用受限教学模型。轨迹回放只重播体验者和碰撞车辆的位置/朝向，不是全场交通、骨骼和天气的录像。记录不足时跳过轨迹播放，保留事故后观察与结果。当前未新增报警、急救或救援角色玩法。

项目没有 Git 仓库。修改前脚本备份位于 `Backups/AccidentExperience-20260905`，包含脚本、字体与四个车辆预制件。
